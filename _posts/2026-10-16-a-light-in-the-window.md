**Это демонстрационная статья.** Здесь собраны примеры разметки и инструкция по публикации. Отдельный шаблон для копирования — [POST_TEMPLATE.md в репозитории](https://github.com/l4iniwakura/l4iniwakura.github.io/blob/main/POST_TEMPLATE.md).

## Основы Markdown

Обычный абзац отделяется от следующего пустой строкой. Можно выделить **важное**, добавить *курсив* или поставить [ссылку на каталоги](/blog/catalogs/).

> Это пример цитаты. В исходном файле строка начинается со знака >.

## Как добавить статью

Создайте в папке `_posts` файл с датой и коротким названием:

```text
_posts/2026-10-17-my-small-discovery.md
```

В начале файла укажите параметры, а после второй строки `---` пишите сам текст:

```yaml
---
title: "Название статьи"
description: "Пара слов о том, что ждёт читателя."
date: 2026-10-17 18:00:00 +0700
categories: [notes]
tags: []
comments: true
---
```

```markdown
Сегодня заметил одну интересную вещь.

## Что получилось

Обычный абзац с **выделением** и *курсивом*.

> Мысль, которую хочется оставить на полях.

- Первое наблюдение.
- Второе наблюдение.
```

Сохраните файл и отправьте изменения в ветку `main`. Jekyll создаст страницу статьи, добавит её в список записей, в подходящие каталоги и в RSS. Вручную дописывать ссылки больше не нужно.

Дата в примере — будущая относительно этой демо-статьи. **Записи с будущей датой не публикуются до сборки после этой даты.** Для публикации сразу поставьте сегодняшнюю или прошедшую дату. В нужный день отправьте изменение в репозиторий, чтобы запустить новую сборку.

## Каталоги

Для примера есть один общий каталог «Заметки». Тематику блога и остальные каталоги вы задаёте сами в `_data/catalogs.yml`.

| Ключ в статье | Каталог | Что туда складывать |
| --- | --- | --- |
| `notes` | Заметки | Общий раздел для примера |

Одна запись может находиться сразу в нескольких каталогах, например `categories: [notes, my-topic]`. Для нового каталога добавьте в `_data/catalogs.yml` его ключ `key`, название `name` и описание `description`. Теги — свободные подписи к статье; они отображаются внизу текста.

## Картинки и подписи

Положите изображение в `assets/images/` и добавьте его в текст:

```markdown
![Описание того, что изображено](/assets/images/my-photo.webp)
```

Описание в квадратных скобках важно для читателей, которые используют экранные дикторы. Для подписи под изображением можно использовать HTML прямо в Markdown:

<figure>
  <img src="/assets/quiet-room.webp" alt="Нарисованная вечерняя комната с лампой-грибом, книгой и папоротником" width="1536" height="1024" loading="lazy">
  <figcaption>Иллюстрация создана с помощью ИИ для оформления блога.</figcaption>
</figure>

```html
<figure>
  <img src="/assets/images/my-photo.webp"
       alt="Описание изображения" loading="lazy">
  <figcaption>Небольшая подпись.</figcaption>
</figure>
```

## Код и маленькие детали

Код оборачивается в три обратные кавычки. После первых кавычек можно указать язык: `javascript`, `python`, `html` или другой. Тогда включится подсветка синтаксиса.

```javascript
const title = "Новая статья";
console.log(title);
```

А второстепенную деталь можно спрятать под раскрывающийся заголовок:

<details>
  <summary>Ещё одна небольшая подсказка</summary>
  <p>Заголовок статьи берётся из поля title. В тексте начинайте разделы с двух решёток, чтобы не дублировать главный заголовок. Для черновика добавьте published: false в параметры статьи.</p>
</details>

## Оставить пару слов

Под статьёй находится giscus. Комментарии хранятся в GitHub Discussions, а сама страница остаётся статической. Для разговора понадобится аккаунт GitHub.

Если конкретной записи комментарии не нужны, укажите `comments: false`. Адрес уже опубликованной статьи лучше не менять: обсуждение связано с путём страницы. При необходимости закрепите адрес через `permalink: /blog/my-small-discovery/` в параметрах.

Этот пример можно изменить или удалить. Адрес статьи оставлен постоянным, чтобы сохранить привязку комментариев.
